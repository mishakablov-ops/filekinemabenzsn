## Шаги

1. **Проект.** `projects/<id>/` по `projects/_template/README.md`. Рабочую копию для рендера сделать из примера:
   `cp -r RS/examples/coffee-agent RS/engine/public/projects/<id>` (история от первого лица) или
   `RS/examples/nuclear-survival` («ты»-инструкция); поменять `id` и пути. Не начинать с нуля.
2. **Факты.** Только реальные цифры со ссылками на источники; факт или цифра каждые 2–3 фразы.
3. **Сценарий** в разметке титров `lead // punch`, один акцент на карточку (`==плашка==`, `[цвет]`, `*курсив*`,
   `~~перечёркивание~~`), хук `%slam` ≤ 7 слов за первые 3 с, фразы по 2–6 слов, почти без тире.
   `script_lint.py` до `LINT OK`.
4. **Голос** Gemini 3.1 Flash TTS «Algenib» (Replicate), по секциям, 2 дубля → проверка Whisper → выбор →
   −16 LUFS → `tts.py --engine audio --tighten 0.25` → `words.json`. Дубли не растягивать и не сжимать.
5. **Раскадровка** `storyboard.py` → `spec.json`: сцена каждые 2,5–3,5 с на слово-якорь (`"at": "@слово"`),
   камера всегда движется (два ключа на сцену), 3D почти в каждой сцене (`Room3D`, `Street3D`, `Blast3D`, `Bars3D`,
   `MacBook`, `IPhone17`), герой в белой кепке и оранжевой кофте, плашки-чек-листы и счётчики поверх.
   `captions: {mode: "editorial", pos: "top", uppercase: true}`. Переходы `push`/`zoom`/`blur`, `whip`, `flash`, `dip`.
6. **Звук.** `autoSfx: false`; `pk-*` почти на каждое ключевое слово, кинематографичные удары только на события,
   один звук два раза подряд не ставить. Музыка `lofi-warm` / `dark-cinematic` 0,10–0,14, duck 0,45, мастер −14 LUFS.
7. **Концовка.** «Кстати, этот ролик тоже собрал агент…» → `IPhone17` (цвет корпуса под тему ролика) разворачивается к
   `TikTokProfile` aipollon (`dark: true`), оранжевая рамка на шапке. В сетке только настоящие обложки канала.
8. **Проверка.** `engine/tools/stills.mjs --qa` по каждой сцене и контактный лист — смотреть самому
   (образец обёртки: `projects/posledniy-chelovek/engine/stills.py` — начало и конец каждой сцены по якорям);
   `render.py <id>` → `qa.py` → 20+ кадров из готового MP4, начало/середина/конец движений, микс в готовом файле.
9. **Выдача.** `RS/engine/out/<id>.mp4` (новые версии `-v2`, `-v3` отдельными файлами). Исходники (`script.md`,
   `spec.json`, `words.json`, `storyboard.py`, голосовые скрипты) скопировать в `projects/<id>/engine/`, строку — в
   `output/README.md`. Новые пожелания пользователя — в `styles/gibrid/README.md` с датой.

## Ограничения среды

- Из облака нет доступа к replicate.com: голос запускается на ПК через `START_WORKER.bat` (задачи `jobs/queue/*.ps1`).
  Задача берёт скрипты из копии репозитория `_sync/<id>/repo` (`projects/<id>/engine/voice_sections.py`), а python,
  ffmpeg, Whisper и ключ — из Reel Studio на ПК. Whisper на ПК: аудио декодировать через ffmpeg (старый PyAV падает),
  числа из Whisper приводить к `int`/`float` перед `json.dumps`. Образец: `projects/posledniy-chelovek/`.
- Рендер можно делать в облаке без видеокарты: `REMOTION_GL=swangle` для `render.py` и `tools/stills.mjs`
  (~1,4 с на кадр на 4 ядрах: 65 с ролика при 60 к/с ≈ 1,5 ч, запускать в фоне). Браузер для Remotion — Playwright
  `chrome-headless-shell` ссылкой в `engine/node_modules/.remotion/chrome-headless-shell/linux64/` + файл `VERSION`.
- Обмен файлами с ПК: `device_stage_files` берёт файлы не глубже 7 папок от подключённой, поэтому результаты задачи
  сначала скопировать в `_sync/<id>/out/`. Файл из `/mnt/project-files/` отправлять на ПК под новым именем и через
  ~10 с после записи (сетевая папка может отдать старую версию). Больше 30 МБ — частями, склеить на ПК.
- Smart App Control на Windows может блокировать `ffmpeg.exe`/`remotion.exe` (код 0xC0E90002). Обходить нельзя, решает пользователь.
- Лимит трат Replicate — $3 на ролик без разрешения пользователя.

## Как скилл учится (после каждого ролика и каждой правки)

1. **Правка пользователя во время работы** («темно», «не так», «вот так огонь») — сразу записать в
   `styles/gibrid/README.md`, раздел «Журнал правок»: дата, цитата пользователя, что меняем. Если это общее правило
   канала — ещё одной строкой в `knowledge/aipollon-knowledge.md`.
2. **После выдачи** спросить одним сообщением, что поправить. Одобренное — в «Что работает», отклонённое — в «Чего не делать».
3. **Удачная модель или приём** — в библиотеку (`blender/library/` или пример в `projects/<id>/`) с описанием в README.
4. **Изменился порядок действий** — поправить шаги в этом `skills/gibrid/SKILL.md`.
5. Коммит в репозиторий: `/gibrid: чему научились на <id>`.
6. Если этот файл заметно поменялся — предложить пользователю обновить скилл `/gibrid` в аккаунте claude.ai
   (карточкой «сохранить скилл»), чтобы копия в аккаунте не отставала.

Новое правило главнее старого; старое не стирать, а помечать «отменено ДД.ММ.ГГГГ».
